Algorithm

      

        
    
          
  1. CX = N − 1 = 19, the number of comparisons in the first pass.
    2. 
          
  2. Start a pass: SI points at ARR[0], DX = CX, swap flag BL = 0.
    3. 
          
  3. Compare ARR[j] with ARR[j+1]. If ARR[j] is larger, exchange them and set BL = 1.
    4. 
          
  4. SI += 2 (each element is one word = 2 bytes). Repeat until DX = 0.
    5. 
          
  5. If BL = 0 the array is already sorted, so stop early.
    6. 
          
  6. Otherwise LOOP: CX − 1. The largest unsorted value is now at the end, so the next pass is one comparison shorter.
    7. 
        

      

    

    

      
Why JBE and not JLE

      

        
CMP AX,[SI+2] subtracts and sets the flags. JBE jumps when CF = 1 or ZF = 1, which is the unsigned "below or equal" test.

        
JLE tests ZF = 1 or SF ≠ OF, the signed test. It reads 8000H – FFFFH as −32768 to −1, so 65535 would be sorted before 0.

        
Switch the toolbar to JLE and run the assignment data to see the wrong order and the program's own check fail.

Time complexity is O(n²) in the worst and average case and O(n) in the best case because of the early exit. Space is O(1): the sort happens in place in ARR.
